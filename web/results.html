Results

Does it work? Measured, not claimed.

Every number on this page comes from python -m evaluation.run_all, scored on simulated plants the models never saw and on NASA's public C-MAPSS benchmark. Where something does not win, this page says so.

1 · Remaining life

How far off is the prediction?

Scored on readings in the wear phase (true remaining life under 100 cycles), where scheduling decisions are made.

2 · Anomaly detection

How early does it notice wear?

Positive means wear has started (wear at or above 0.25), which is the point P where a fault becomes detectable. The comparison is a fixed vibration threshold at ISO 10816-3 zone C.

Reproduce it

Two commands

The suite trains nothing new for the twin results (it reuses the cached models, or trains them once), runs about 8 minutes on a laptop CPU, and rewrites this page's data file and docs/RESULTS.md.

python -m unittest discover -s tests -p "test_*.py"   # 48 tests
python -m evaluation.run_all --quick                   # about 8 min; --cmapss-only adds the NASA benchmark
  • The twin is our own simulator, so twin scores show the system works end to end; the C-MAPSS benchmark is the check on public data.
  • The perfect-model policy uses the true wear, which no real system can see: it is an upper bound, not a result.
  • The fixed schedule is tuned on the same plants it is scored on, which flatters it; the copilot is not tuned on them.
  • Repair time after a breakdown (3×) is an assumption; the sensitivity chart shows how the conclusion changes with it.
