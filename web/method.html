How it works

From a vibration reading to a signed-off repair

A simulated plant streams sensor readings. Two models turn them into "is something wrong?" and "how long is left?". Rule-based agents turn that into a dated work order with a cited procedure, and a supervisor approves it. Every step below links to the code that does it.

Architecture

Five layers, one loop

The loop closes in the twin: an approved work order interrupts the simulated machine, it is serviced, and its readings return to normal. The forecast and the evaluation suite reuse the same twin to test policies offline.

The data

A plant we can break safely

We have no real plant to run machines to failure in, so the project simulates one. Each machine wears a little every cycle; its sensors respond to that wear with noise; and when wear reaches 1.0 it breaks. The models never see the wear itself, only the sensors.

weart+1 = weart + 𝒩(μ, σ) · per-cycle wear, μ and σ per machine
vibration = 0.5 + 4·wear1.8 + 𝒩(0, 0.08) mm/s · crosses ISO zone C (2.8) near wear 0.64
temperature = 38 + 35·wear1.5 + 1.5·sin(t/300) + 𝒩(0, 0.6) °C
cycle time = nominal × (1 + 0.4·wear) · a worn machine is slower
failure when wear ≥ 1.0 → repair takes 3× a planned service (an assumption, tested in Results)

The curves are hand-chosen, not fitted to a real machine: monotonic and accelerating, like the exponential degradation used to generate NASA's C-MAPSS data [1], and scaled so vibration moves through the ISO 10816-3 zones [5] over a part's life. That is why the suite also includes a benchmark on C-MAPSS itself (evaluation/cmapss_benchmark.py).

The models

Two questions, two models

Both use only what a real plant could measure: vibration, temperature and the age of the part since its last service. Training uses one simulated plant; every score in Results comes from other plants the models never saw.

Temporal convolutional network [2], after Lövberg [3]

Inputs
last 3-30 readings: vibration, temperature, their changes, rolling mean and spread, part age
Target
cycles to failure, capped at 100 (piecewise-linear [6])

The decision rule

Remaining life becomes a clock time

A prediction that is too late is far worse than one that is too early, so the scheduler only trusts 85% of it: safe = 0.85 × predicted RUL. The safe life, multiplied by the machine's current cycle time, becomes a deadline in clock time.

Watchpredicted RUL below 90 cycles: wear is under way
Service soonsafe RUL below 60 cycles: plan it into the shift
Service nowsafe RUL below 30 cycles: a work order is drafted for approval
Downthe machine broke; repair takes about 3× a planned service

The agents are a LangGraph state graph of rule-based steps: Monitor → Diagnosis (retrieves the machine type's procedure from a ChromaDB store and cites it) → Scheduler → Report. No language model is involved, so every decision can be traced and unit-tested. By default the copilot only drafts work orders; a supervisor approves them. COPILOT_AUTONOMY=1 lets it act alone, for a lights-out cell.

Design decisions

What we chose, and what we chose against

DecisionAlternatives consideredWhy
Simulated plant (SimPy)A public dataset onlyDatasets are recordings: you cannot act on them. A twin lets the copilot schedule a service and see the effect, and lets us compare policies on identical futures. Real data is still used, for the C-MAPSS benchmark.
TCN for remaining lifeLSTM, gradient boostingTrains in parallel, stable gradients, a 61-reading receptive field from 4 layers. Gradient boosting is kept as a fallback and as a baseline, so the TCN always has something simpler to beat.
Age since service as an input, not the lifetime counterCycle countThe lifetime count keeps rising after a part is replaced, so the model would think a fresh part is old. Part age is known from the maintenance log.
Never use wear as an inputFeed the simulator's wearWear is invisible in a real plant. Using it would make the scores meaningless (label leakage).
Isolation Forest on the healthy envelopeFit on all data; a fixed threshold; an autoencoderNeeds no failure labels. Fitted on all data it learned that wear is normal and missed most worn readings; fitted on fresh-after-service data it detects the onset of wear early.
RUL capped at 100 cyclesRaw cycles to failureA healthy machine at 300 or 280 cycles left looks identical. Capping is standard practice on C-MAPSS [6].
15% safety marginAct on the raw predictionLate predictions cause breakdowns; early ones only waste some part life. Results reports how often predictions are late.
Rule-based agents, no language modelAn LLM agentMaintenance decisions must be repeatable and auditable, and aerospace plants often cannot send data to cloud services. Each rule is unit-tested.
Human approval by defaultFully autonomous schedulingStopping a machine has a cost; people need to trust the system first. Autonomy is one switch away.
TF-IDF retrieval filtered by machine typeNeural embeddingsSix short procedures; filtering by type is exact and needs no model download. Embeddings would matter for free-text search over many manuals.
Three.js without a build stepReact, a game engineRuns from the Python server alone, offline. The cost is large hand-written JavaScript files.
